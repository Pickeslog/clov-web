# 마스코트 스프라이트 정규화 도구

`src/assets/mascot/_template/README.md`의 이미지 계약 중 **"모든 상태에서 캐릭터가 비슷한
화면 점유율과 여백을 갖도록 한다"** 를 실제로 강제하는 도구다.

## 왜 필요한가

마스코트는 `height`만 고정하고 `width: auto` + `object-fit: contain`으로 그린다(`Mascot.css`).
그래서 **원본 비율이 상태마다 다르면 렌더 박스 가로폭이 같이 달라지고, 상태가 바뀔 때마다
캐릭터가 좌우로 움직인다.**

실제로 그랬다.

| | 정규화 전 | 후 |
|---|---|---|
| crobi 9종 | 366x640 ~ 1086x1448 → 박스 **103~135px** | 440x680 → **116px 고정** |
| tako-gun 9종 | 640x640 + 1254x1254 | 640x640 고정 |
| rob 9종 | 900x510 (원래부터 단일 규격) | 그대로 |

용량도 같이 해결된다 — crobi 8.5MB → 3.0MB, tako-gun 7.3MB → 2.6MB.
장당 ~300KB로 기존 마스코트 관례(버거노인 256KB · 김철수 248KB)와 같은 수준이다.

## 쓰는 법

```powershell
# 1. 드라이런 — 표만 보고 임시 폴더에 결과물을 만든다
.\normalize-sprites.ps1 -Character tako-gun

# 2. 눈으로 확인
.\contact-sheet.ps1 -Dir $env:TEMP\mascot-normalize\tako-gun -Out check.png

# 3. 괜찮으면 덮어쓴다
.\normalize-sprites.ps1 -Character tako-gun -Apply
```

`-Apply` 없이 돌리면 원본을 건드리지 않는다. 이게 기본값이다.

### ★ 덮어쓰기 전에 원본을 보존할 것

생성된 고해상도 원본은 `web-design-repository/test-web-design/02-main/assets/<캐릭터>/`에 둔다.
정규화본은 앱이 쓰는 축소본이라 원본을 대신하지 못한다. 07-31에 버거노인 레이어 분리본을
디자인 레포로 보낸 것과 같은 처리다.

## 무엇을 맞추는가

| | 기준 | 왜 |
|---|---|---|
| **배율** | 알파 면적의 제곱근 | 면적은 크기의 제곱에 비례하고 포즈에는 잘 안 흔들린다. **bbox 높이로 맞추면 웅크린 `pencil`이 부풀고, 줄에 매달린 `pulled`이 쪼그라든다.** 머리 폭은 벌린 팔·소품에 오염돼 못 쓴다 |
| **세로** | 알파 박스 하단(발바닥)을 공통 baseline에 | rob이 하단 여백 48px로 고정해 둔 것과 같다 |
| **가로** | 무게중심을 캔버스 중앙에 | bbox 중앙으로 하면 `pencil`의 연필처럼 한쪽으로 튀어나온 소품이 몸통을 반대로 밀어낸다 |

기준 스프라이트는 항상 `default.png`(rob은 `idle.png`)다 — 지금 사용자가 보고 있는 그림이라
이걸 안 움직이는 게 맞다. 캔버스와 하단 여백도 기본적으로 기준 스프라이트에서 가져온다.

이미 정규화된 폴더에 다시 돌려도 안전하다 — 배율이 1로 수렴한다(실측 0.996~1.002. 정확히
1이 아닌 건 리샘플이 안티에일리어싱 알파를 0.4%쯤 바꾸기 때문이고, 누적되지 않는다).

## ★ 언제 쓰면 안 되는가

**캔버스가 이미 단일 규격이면 웬만하면 돌리지 마라.**

이 도구의 주 효과는 렌더 박스 가로폭을 고정해 좌우 흔들림을 없애는 것인데, 캔버스가 이미
하나면 그건 달성돼 있다. 남는 건 캔버스 안쪽 발바닥 정렬뿐이고 그건 포즈에 따라 원래
다를 수 있다(매달린 `pulled`, 웅크린 `scared`).

그런데 면적 기준은 **별·모션선·돋보기처럼 포즈마다 붙는 "잉크 양"을 "크기 차이"로 오독**한다.
멀쩡한 세트에 돌리면 되레 어긋난다. 실측 두 건:

| | 상태 | 돌리면 |
|---|---|---|
| `rob` | 900x510 단일 · 하단 여백 48px 고정 (손으로 한 세트로 그림) | 배율이 **0.948~1.02**로 흩어짐 |
| `kim-cheolsu` | 640x640 단일 · 이미 정렬됨 | 배율 **0.99~1.09** · 용량 **2.3MB → 2.9MB로 증가** |

이 도구는 **캔버스와 프레이밍이 제각각인 생성 결과물**을 맞추는 용도다(crobi·tako-gun이 그랬다).

폴더가 이미 단일 규격이면 스크립트가 경고를 낸다. **판단 기준은 드라이런 표의 `scale` 열이다
— 1에서 멀면 오독이니 돌리지 말 것.** `contact-sheet.ps1`의 `OVERLAY` 칸도 같이 본다.
윤곽이 이미 모여 있으면 손댈 이유가 없다.

경고에 같이 찍히는 하단 여백 편차는 **참고값일 뿐 판단 기준이 아니다.** kim-cheolsu는
46~71px로 편차가 큰데도 정렬이 맞아 있다 — 매달리거나 웅크린 포즈 때문이다.

### 캔버스를 넘는 그림

`pulled`처럼 그림이 프레임 밖으로 이어지는 포즈가 있다. crobi의 `pulled`은 **줄에 매달린
그림**이라 맨 위 얇은 사선이 높이를 1.26배로 부풀린다 — 이걸 다 담으려고 캔버스를 키우면
나머지 8종이 그만큼 작아진다. 줄은 잘려서 프레임 밖으로 이어지는 게 낫다.

그래서 넘치면 막지 않고 경고만 낸다. 의도한 게 아니면 `-CanvasH`/`-CanvasW`를 키운다.

## 제약

- **Windows 전용**(`System.Drawing`). 새 npm 패키지를 안 쓰려고 이렇게 했다 — `AGENTS.md`의
  "New packages require team confirmation". 2026-08-01에 로고를 1,019KB → 13KB로 줄일 때
  쓴 방법과 같다.
- `SpriteTool.cs`는 **ASCII만 쓴다.** `Add-Type`이 임시 `.cs`로 써서 컴파일하는데 한글 주석이
  들어가면 이 환경에서 컴파일이 깨졌다.
- 검증을 브라우저로 하지 않는 이유 — Browser pane이 표시되지 않으면 `new Image()` 디코드가
  실패하고 스크린샷도 안 된다(`fetch`는 200을 주기 때문에 "경로는 맞는데 이미지만 깨진 것"으로
  오진하기 쉽다). PNG로 뽑으면 그 제약을 안 탄다.
